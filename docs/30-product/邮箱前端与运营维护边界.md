# 邮箱前端与运营维护边界

## 目的

本文档用于把旧 `legacy source: 邮箱维护指南.md` 中关于前端 owner 路径、BFF 路由、ops adapter 的维护约束，收口成新的专题文档。

---

## 1. 当前正式 owner 路径

邮箱前端当前正式 owner 路径是：

- `web/src/features/mailbox/`

这条路径 owner：

- 用户侧邮箱页面逻辑
- server helper
- account/ops adapter
- mailbox feature 内部样式与工具

---

## 2. 当前正式 API 路由边界

邮箱前端当前默认通过：

- `web/src/app/api/account-mailbox/`

暴露 BFF 路由。

正式要求：

- route 文件保持极简
- 主要逻辑进入 feature helper / adapter

不应继续在 route 文件里散落复杂 mailbox 逻辑。

---

## 3. 当前正式 ops 边界

`/ops/account/mailbox` 当前默认应通过：

- feature 内的 ops adapter

来访问内部接口。

也就是说，后续 mailbox ops 相关变更，应优先收口在 feature adapter，而不是继续在页面和 actions 文件里重复写请求逻辑。

---

## 4. 当前正式兼容策略

旧的：

- `account-client`

当前仍可保留兼容导出，但新功能默认应进入 feature adapter 再导出。

这条规则的意义是：

- 防止 mailbox 逻辑再次散落回通用 client
- 保持 feature owner 边界稳定

---

## 5. 当前正式维护规则

后续若改邮箱前端或运营页，默认检查：

1. 新逻辑是否继续收口在 `features/mailbox`
2. route 文件是否仍保持薄层
3. ops 页面是否继续通过统一 adapter 调用
4. 是否又把 mailbox 逻辑写散回 `account-client`

---

## 6. 当前正式结论

从现在开始，邮箱前端与运营维护边界以本文为准；旧 `legacy source: 邮箱维护指南.md` 继续保留为 source material，但不再作为新的主文档。
