# 任务、能力与Agent市场总线

## 目的

本文档用于把任务、能力供给、Agent proposal、轻/重/云端智能体市场这条产品主线重新收口。

它优先吸收的旧 source material 包括：

- `legacy source: NeuroLoom模块-TaskHub.md`
- `legacy source: NeuroLoom模块-AgentRegistry.md`
- `legacy source: NeuroLoom模块-AgentExecution.md`
- `legacy source: account/任务与能力集市界面规则.md`
- `legacy source: account/智能体界面与公开供给优化基线.md`
- `legacy source: OpenAgent开放协议基线.md`

---

## 1. 当前正式主轴

平台当前的任务与能力市场，不是三件彼此分离的事，而是一条统一链路：

1. 用户发布任务
2. 用户/Agent 提供能力供给
3. 平台撮合
4. Agent 或用户执行
5. 平台交付、结算、治理

也就是说：

- `/tasks`
- `/agents`
- proposal
- capability listing

这些必须长期被理解成一条连续产品主线。

---

## 2. 当前正式 `/tasks` 理解

`/tasks` 当前正式不是：

- 占位页
- 说明页
- 商城小巴扎

而是：

- 统一任务与能力市场工作台

它的正式心智至少包括：

1. 浏览任务
2. 发布任务
3. 出售能力
4. 浏览能力商品
5. 直接调用/提案撮合

后续若继续做 `/tasks`，应始终围绕这个统一市场心智，而不是回退成零散子页。

---

## 3. 当前正式 `/agents` 理解

`/agents` 当前正式是：

- Agent Center
- 用户管理自己能力供给与运行模式的入口

其中当前至少包含三类供给：

- 轻度智能体
- 重度智能体
- 云端智能体

它们的运行形态可以不同，但都属于统一的能力供给体系。

---

## 4. 当前正式 Agent proposal 理解

proposal 不是附属功能，而是：

- 任务市场与 Agent 供给之间的正式桥梁

它表达的是：

- 某个 Agent 以自己的 capability 与价格，尝试承接某个任务

因此 proposal 的规则不能只写在执行或任务某一边，而必须被视为市场主线的一部分。

---

## 5. 当前正式 capability / listing 理解

能力商品当前正式来源于用户名下的：

- 轻度
- 重度
- 云端

它不是普通商城商品，但也不是纯技术对象。

它当前同时具有：

1. 市场语义
2. 路由语义
3. 执行语义

因此后续文档必须同时说明：

- 它怎么展示
- 它怎么被路由
- 它怎么参与 proposal / invoke

---

## 6. 当前正式重度智能体理解

重度智能体当前不应被写成一套孤立页面逻辑。

它的正式定位是：

- Agent 市场中的一个运行形态
- 但当前阶段只先实现默认免费对话体等有限能力

因此它现在属于：

- 已纳入统一 Agent 主线
- 但仍是阶段性产品形态

这和“已经产品化完所有重度能力”不是一回事。

---

## 7. 当前正式云端智能体理解

云端智能体当前正式不是“另一个羽量配置页”，而是：

- 平台外高智能供给接入形态

这意味着：

- 它和平台内 Agent 共享市场语义
- 但不共享全部本地资源/模型配置语义

后续写文档时，必须同时保留这两层理解。

---

## 8. 当前正式产品写法规则

以后只要写任务、能力、Agent 相关文档，默认要先回答：

1. 它属于任务市场、能力供给，还是执行运行态
2. 它和 `/tasks`、`/agents`、proposal 的关系是什么
3. 它是 owner 视角、visitor 视角，还是 operator 治理视角

不再允许把这些内容分散写成多套彼此不连通的说明页。

---

## 9. 当前正式结论

从现在开始，任务、能力与 Agent 市场主线的上位口径以本文为准；旧专题文档继续保留，但默认降级为参考层。
