# 商品、资产与权益总线

## 目的

本文档用于统一商品、订单、资产、钱包、权益、凭证发放这条产品主线。

## 1. 当前正式主轴

商品与资产主线当前正式由以下环节构成：

1. 商品
2. 订单
3. item / asset
4. 钱包与账本
5. 权益/资格发放
6. 问题申报、补位、复核与后续治理

这是一条连续链路，不应再被拆成互不相干的几组页面说明。

---

## 2. 当前正式钱包理解

平台钱包当前是：

- 平台内部正式价值底座

而不是：

- 外部链钱包
- 通用加密资产托管系统

当前正式三货币主线仍应理解为：

- `mira`
- `obsidian`
- `opinionTickets`

展示名可继续通过显示层 alias 处理，但内部 canonical key 不应随意漂移。

---

## 3. 当前正式商品/订单/item 理解

商品链路当前正式理解为：

1. 用户购买商品
2. 形成订单
3. 平台发放 item / unit / 权益
4. 如遇问题，进入 issue / replacement / manual review / reconcile

因此后续任何“商品是否完成”的判断，都不应只看：

- 商品展示页

而必须看完整链路是否闭环。

---

## 4. 当前正式权益与凭证理解

产品卖给用户的长期正式心智不是：

- 把上游真实 provider secret 直接卖给用户

而是：

- 卖平台资格
- 卖平台访问能力
- 卖平台代理能力
- 必要时再通过产品规则导出用户侧可见凭证

这条边界必须和 AI Gateway 的两层 key / provider credential 模型保持一致。

也就是说：

- 用户拿到的是平台视角能力
- 真正的上游 provider secret 仍由平台统一治理

---

## 5. 当前正式“羊毛派 / 已购权益领取台”理解

这条产品线当前正式语义是：

- 用户已购权益的聚合与领取台

它不是：

- 另一个普通商品页
- 也不是 operator 凭证仓库页面

在这里必须长期区分两类能力：

1. 平台直接代理型能力
2. 用户可导出/可轮换/可领取的用户侧凭证能力

---

## 6. 当前正式问题处理链路

商品与资产相关问题当前正式应有完整治理链：

1. issue report
2. manual review
3. replacement / reconcile
4. anomaly / SLA / operator intervention

因此后续任何产品文档，不应再只写“发放成功”，而不写：

- 出问题怎么办
- 谁处理
- 何时重试
- 何时自动升级

---

## 7. 当前正式产品写法规则

以后只要写商品、资产、权益、钱包、凭证发放相关文档，默认要先说明：

1. 用户拿到的是平台资格、平台代理能力，还是用户侧可导出凭证
2. 这条能力的 owner 是平台域、账户域，还是 AI gateway
3. 出问题后走哪条治理链

不再允许只给一个“商品说明页”式的静态描述。

---

## 8. 当前正式结论

从现在开始，商品/资产/权益主线的上位口径以本文为准；旧专题文档保留为 source material，但不再自动具备最高权威。
