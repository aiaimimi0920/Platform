# 商城、小集市与权益发放实施边界

## 目的

本文档用于把旧 `legacy source: 商城模块化维护指南.md`、`legacy source: 羊毛派模块化维护指南.md` 等工程维护约束收口成新的专题，重点回答：

1. 商城 / 小集市的前端 owner 路径
2. 权益发放与羊毛派的工程边界
3. 平台 source-of-truth 与用户侧 feature 的关系

---

## 1. 当前正式 owner 路径

### 1.1 商城 / 小集市

前端正式 owner：

- `web/src/features/account-commerce-center/`

### 1.2 羊毛派 / 已购权益领取台

前端正式 owner：

- `web/src/features/account-benefit-center/`

旧 `account-home/*` 路径当前只保留兼容 shim，不再承载新主实现。

---

## 2. 当前正式 source-of-truth

### 2.1 商城 / 小集市

平台主事实链仍在：

- 商品 / marketplace / product-order-item

### 2.2 羊毛派 / 权益领取

产品规则与发放链继续复用：

- benefits
- credential pools
- product/order/item
- gateway/new_api 访问主线

所以：

- feature 独立 != 服务独立
- UI owner 独立 != 业务事实层独立

---

## 3. 当前正式产品边界

### 3.1 `/products` 与 `/marketplace`

负责：

- 商品浏览
- 交易
- listing

### 3.2 `/benefits` / 羊毛派

负责：

- 已购权益聚合
- 凭证导出/轮换/访问入口
- 领取台视角

两者不能再混成一页心智。

---

## 4. 当前正式能力分层

后续相关文档和实现必须继续区分：

1. 商品交易能力
2. 权益资格能力
3. 用户侧可领取/可导出凭证能力
4. 平平台代理能力

不要再把“用户可见的一个按钮”当成这四层已经自动统一。

---

## 5. 当前正式维护规则

后续若改商城、小集市、羊毛派相关实现，默认检查：

1. 商城逻辑是否继续收口在 `account-commerce-center`
2. 羊毛派逻辑是否继续收口在 `account-benefit-center`
3. 是否误把 operator/库存/真实凭证治理写回用户侧 feature

---

## 6. 当前正式结论

从现在开始，商城、小集市与权益发放的工程维护边界以本文为准；旧 `legacy source: 商城模块化维护指南.md` 与 `legacy source: 羊毛派模块化维护指南.md` 继续保留为 source material，但不再作为新的主文档。
