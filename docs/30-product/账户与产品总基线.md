# 账户与产品总基线

## 目的

本文档用于在 `docs/` 中重新收口账户、产品、权益、任务、Agent 等产品主线。

legacy account docs tree 与大量 `NeuroLoom模块-*` 文档里有很多具体规则，但它们当前已经过于分散。本文负责给出新的产品总线。

---

## 1. 当前正式产品主轴

平台当前应理解成四条主轴：

1. **账户主轴**
   - 用户是谁
   - 用户看见什么
   - 用户拥有什么资格

2. **资产主轴**
   - 钱包
   - 账本
   - 商品
   - 订单
   - item / asset / redemption

3. **任务与能力主轴**
   - Task Hub
   - 能力市场
   - Agent 能力供给
   - 履约与交付

4. **运营治理主轴**
   - operator
   - 人工复核
   - 仲裁
   - 风控

---

## 2. 当前正式账户边界

账户域当前正式 owner 包括：

- identity
- `/v1/me`
- mailbox
- announcements
- benefits
- user progression
- reputation

其中邮箱与真实邮箱相关能力当前必须继续理解为：

- 平台邮箱/投递/入口层
- 不是把平台整体变成完整通用邮箱产品

---

## 3. 当前正式三视图产品语义

### 3.1 Owner View

用户已登录后看到自己的内容。

### 3.2 Visitor View

外部访客看公开档案，只读。

### 3.3 Operator View

平台运维与治理专用。

当前所有产品交互都必须先判断：

- 这是 owner 行为
- visitor 行为
- 还是 operator 行为

不能继续在组件或文档层混掉。

---

## 4. 当前正式商品与权益理解

平台卖给用户的长期正式心智不是：

- 上游真实 provider secret

而是：

- 平台资格
- 平台访问能力
- 平台代理能力
- 平台可导出或可调用的资源

这点和 AI gateway 的两层 key / 凭证模型必须保持一致。

---

## 5. 当前正式任务与能力市场理解

`/tasks` 当前属于 Owner View 下的统一任务与能力市场工作台。

长期正式心智是：

- 用户发布任务
- 平台匹配能力供给
- Agent/能力完成交付
- 平台承担履约、结算、治理

不得再把它回退成：

- 说明页
- 临时占位页
- 四个互不相干的小面板组合

---

## 6. 当前正式 Agent 理解

平台中的 Agent 当前至少包括：

- 轻度智能体
- 重度智能体
- 云端智能体

长期正式心智是：

- Agent 是平台供给单元
- 其接入资格、执行与交付都要落到平台统一协议与平台权益体系里

而不是：

- 用户随便填一个裸 `api key` 就等于正式能力链完成

---

## 7. 当前正式 operator 理解

operator 负责的是：

- 治理
- 运维
- 调整
- 审核
- 审计

而不是把 operator 页面本身变成业务真相层。

因此产品文档后续必须明确区分：

- operator 可见
- operator 可操作
- operator 是 owner

这三件事不是同一个概念。
