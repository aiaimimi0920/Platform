# Repository security and quality baseline

## Existing validation remains authoritative

`Platform CI` retains `npm run ci`, which runs repository contracts, production
npm audit, workspace builds, unit and Vitest suites, type checking, and OpenTofu
format/provider-schema validation. Compose topology and existing Windows release
contracts remain separate jobs. This update does not deploy or change release
publication, container publication, infrastructure backends, or credentials.

## Added controls

- Repository Quality runs on pull requests, main, manual dispatch and weekly:
  actionlint 1.7.12 validates every workflow; Gitleaks 8.30.1 scans complete
  committed history with fully redacted output and a nonzero finding exit code.
- Both CLI archives are from their official GitHub releases, fixed by SHA-256
  in `scripts/ci/install-tool.sh`. A download or digest failure fails the job.
- CodeQL uses pinned v4 actions with no-build JavaScript/TypeScript and Actions
  extraction and `security-extended` queries. Only analysis jobs get
  `security-events: write` and `actions: read` for SARIF publication.
- OSV Scanner 2.5.1 scans `package-lock.json`, the single lock for all ten npm
  workspaces, including development dependencies. Findings fail the job; no
  vulnerability exception was introduced. OSV does not cover OpenTofu provider
  binaries, OS packages, or deployment images through this npm-only scan.
- Existing npm/Actions Dependabot coverage gains bounded grouped routine npm
  proposals, plus Docker base images.
  Version PRs are not automatically merged. Security updates are not deferred
  by the routine version-update cooldown.

## Local checks

Run `node --test scripts/ci/security-baseline.test.mjs scripts/repository-contract.mjs`.
On Linux, install the two tools with `bash scripts/ci/install-tool.sh actionlint`
and `bash scripts/ci/install-tool.sh gitleaks`, then run `.tmp/ci-tools/actionlint`
and `.tmp/ci-tools/gitleaks git --redact=100 --no-banner --exit-code=1 --log-opts="--all" .`.
Run OSV 2.5.1 with `scan source --lockfile=./package-lock.json` and the existing
`npm run ci` gate. Local missing Docker/OpenTofu capabilities must be disclosed;
GitHub Actions must validate those stages before merge.

## Review and limitations

Review exact source and test the exact PR head before merge; check main afterward.
New scanner findings require triage, not a silent broad allowlist. If a real
credential is detected, revoke it and coordinate cleanup without printing it in
issues or logs. A green scan does not prove absence of unknown flaws or secrets.

This baseline does not change branch protection, account permissions, paid
security products, GitHub secret-scanning/push-protection settings, or licenses.
Those repository/account settings are separate from workflow checks. Existing
CI contracts/builds are preserved rather than copied from a desktop project.

## Historical secret-scan triage

The initial full-history scan found ten generic-key candidates. Each was reviewed:
five synthetic test values, two public discount-benefit identifiers, two short
deterministic credential-documentation placeholders, and one public OAuth client
identifier (not its client secret). `.gitleaksignore` contains only their exact
commit/path/rule/line fingerprints. `scripts/ci/gitleaks-reviewed-findings.json`
records a reason for every entry and the contract requires an exact one-to-one
match. No path, rule or credential-shaped pattern is broadly exempted. A new
value or commit remains subject to scanning and requires separate review.

## Initial dependency remediation

The first whole-lock OSV scan found nine affected package names. Compatible
updates cover Next 16.3.3, Fastify 5.12.x, fast-uri 3.1.8, Vitest/mocker 4.1.11,
sharp 0.35.5, nanoid 3.3.19 and baseline-browser-mapping 2.11.x plus their resolved
transitive dependencies. Locks are generated by npm, not manually rewritten.

Nodemailer needs 10.0.13 for the remaining published fixes. Its [v10 migration](https://github.com/nodemailer/nodemailer/releases/tag/v10.0.0)
raises Node support to >=20 and provides both ESM and CJS exports; the project's
Node 22 baseline and existing dynamic-import/createTransport/sendMail calls
satisfy this boundary. The production mail code and auth flow are unchanged.
The existing optional-peer overrides follow the same corrected version; Auth.js
mail login is not configured. A loopback-only SMTP regression exercises the
actual imported package, authentication, text/HTML and Unicode composition,
Reply-To and 550 rejection propagation without sending external email.

Revert the dependency manifests, overrides and generated lock together for a
controlled rollback; do not remove the scanner, hide its findings, or deploy
an affected rollback without a separate risk decision. No dependency exception
is introduced by this remediation.

The final lock uses exact Nodemailer 10.0.13 in the worker and both overrides.
A follow-up scan caught GHSA-g57g-f23g-4646 in the initially evaluated 10.0.6;
the upstream patch requires >=10.0.9, so the candidate was updated and rescanned
rather than suppressing this finding.

## OpenTofu updater compatibility

The first attempted Terraform Dependabot update failed because its bundled
Terraform 1.16.4 does not satisfy this repository's intentional OpenTofu
`>=1.12.0, <1.13.0` contract. See [the observed updater run](https://github.com/aiaimimi0920/Platform/actions/runs/36699317653).
That unsupported updater entry has been removed. Do not widen the infrastructure
version constraint, replace OpenTofu, or enable real plan/apply to make a bot pass.

OpenTofu formatting, backend-disabled/read-only initialization and provider-schema
validation remain mandatory in the existing CI. Provider lock upgrades require
explicit compatible-tool evaluation and reviewed lock regeneration until an
updater supports this pinned toolchain. npm, Actions and Docker Dependabot jobs
remain enabled. This is a documented automation gap, not vulnerability suppression.
