# 历史构建产物清理基线

## 目的

本文档用于承接旧 `legacy source: NeuroPlatform历史构建产物清理脚本.md` 的长期使用说明。

---

## 1. 当前正式脚本

当前正式清理脚本是：

- `scripts/cleanup-neuroplatform-build-artifacts.ps1`

---

## 2. 当前默认清理范围

默认只清理明显属于历史构建/运行时产物的目录，例如：

- `.runtime/` 中陈旧的 `cargo-target-*`
- `gateway/` 下陈旧的 `target*` 与 `.runtime`
- `tmp/` 下陈旧的直接子项

默认不清理：

- 源码目录
- `.git`
- `output`
- `web`

这里的 `output/` 语义是：

- 默认不在日常清理脚本里物理删除
- 但也不应默认继续被 git 跟踪

也就是说，`output/` 当前更接近：

- 本地 focused / fixture / live 验收归档
- 可留在工作树
- 不默认长期留在版本控制

同样地，本地自动化辅助目录：

- `.playwright-cli/`
- `test-results/`

当前也默认按“本机运行快照/状态目录”处理：

- 可留在工作树
- 不默认长期留在版本控制
- 也不作为日常构建产物清理脚本的默认物理删除对象

同类的本地工具辅助目录还包括：

- `.codex-preview/`
- `.codex/preview-logs/`
- `.playwright-mcp/`
- `.input.json`

它们当前更接近：

- agent/browser 预览现场
- mcp bridge 调试日志
- 一次性执行输入快照

因此当前同样默认：

- 可留在本地工作树
- 不默认长期留在版本控制
- 不作为日常清理脚本的默认物理删除对象

对 `.runtime/`，当前也应优先区分：

- 严格 whitelist 明确保留的最小 tracked 证据
- 其余默认只属于本地运行现场的内容

因此在日常开发中：

- `.runtime/**` 当前默认可直接本地忽略
- 真正需要长期 tracked 的 `.runtime` 内容，由 repo-level strict 白名单单独控制

`gateway/` 子树下的这类本机运行目录也按同样原则处理：

- `gateway/.linux-target/`
- `gateway/.runtime/`
- `gateway/gateway/.runtime/`
- `gateway/*.log`

它们当前更接近：

- gateway 本机构建输出
- browser/runtime pool 调试现场
- 本机直接启动 gateway 的日志副产物

因此当前同样默认：

- 可留在本地工作树
- 不默认长期留在版本控制
- 不作为 canonical repo evidence

根目录下的这类本机审计材料也按同一口径处理：

- CURRENT_MAIN_REPO.md（本地状态笔记）
- `*-console-login-required.png`

它们当前更接近：

- 本地状态备忘
- 某次登录/挑战 gate 的现场截图

因此当前也默认：

- 可留在本地工作树
- 不默认长期留在版本控制
- 不作为正式仓库文档或 canonical evidence

对 `gateway/` 子树里的这类本地草稿/残留文件也应按相同口径处理：

- gateway/FREEBUFF_REFRESH_PRINCIPLES.md（gateway-root 本地草稿来源）
- `gateway/src/protocol/accio.rs`

它们当前更接近：

- 尚未迁回 canonical docs 的 gateway-root 草稿
- 模块目录重构后遗留的 local duplicate source

因此当前也默认：

- 可留在本地工作树
- 不默认长期留在版本控制
- 需要正式保留时先迁到 canonical docs / canonical module owner

---

## 3. 当前使用原则

当前清理仍必须遵守：

- 先看候选项
- 再执行删除
- 路径必须位于仓库边界内

不能把构建产物清理误做成：

- 全盘无差别删除
- 对运行中目录的盲删

---

## 4. 开发镜像清理基线

当前开发流程默认允许：

- 围绕某个服务商的某条实现线反复编译并产出新的开发镜像

这本身属于正常开发行为，不应被视为异常。
但镜像管理当前必须同时满足：

- 冗余镜像及时清理
- 关键测试证据优先保留
- 镜像预算按“服务商 + 实现线”收口

### 4.1 冗余镜像定义

例如：

- 先编译版本 `A`
- 发现功能缺失或逻辑错误
- 修改代码后再编译版本 `B`

若 `A` 已不再承担当前有效回归、调试、复现实验价值，则 `A` 当前应视为：

- **冗余镜像**

并默认应删除。

### 4.2 关键测试证据保留

删除冗余镜像前，若该镜像仍有核查价值，默认优先保留：

- `output/` 中的 focused / fixture / live 归档
- 关键日志
- caller-visible 回包
- 关键截图 / 抓包 / summary

也就是说：

- 优先保留证据
- 不默认长期保留旧镜像本体

### 4.3 当前预算

当前正式预算是：

- **一个服务商的一条实现线，理论上最多允许并存 5 个开发镜像**

若需要产出第 6 个及之后的新镜像，默认必须先：

1. 删除旧的无效开发镜像
2. 腾出空间
3. 再继续产出新镜像
