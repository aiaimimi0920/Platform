# 本地预览与端口分配基线

## 目的

本文档用于承接旧 `legacy source: 本地预览端口规则.md` 中仍然有效的长期开发约束。

---

## 1. 当前正式规则

本地 UI 预览 / 验证默认应：

- 从 `30000` 起使用新的预览端口序列
- 每次新实例按 `+2` 递增

例如：

- `30000`
- `30002`
- `30004`

---

## 2. 当前正式 helper

默认 helper：

- `deploy/start-web-preview.ps1`

若需要重建本地 `docker compose` 的 `web` 服务并拿到新的页面实例：

- `deploy/restart-web-next-port.ps1`

两个 helper 共享同一跨进程端口分配锁。通用预览只有在 Web `/ready` 成功且 `/api/auth/providers` 明确包含 `local-dev` 时才允许返回成功；临时 env 必须在 Docker 创建容器后删除，未就绪实例必须清理。Compose Web 重启必须在健康检查后原子提交 `.runtime/local-web-port.txt`；重启失败时不得覆盖旧 state，只能按容器 ID 删除本次新建的替换实例，不能按 Compose service 名误删身份未变化的旧实例，并且必须恢复调用前的 `WEB_HOST_PORT`。启用 heavy-task lease 时必须通过当前 PowerShell host 的无 profile 子进程执行 claim/release，两个阶段的非零退出码都必须可观测，同时 release 失败不得静默替换已发生的主预览错误。

本地集成 Compose 与 `deploy/start-web-preview.ps1` 都运行镜像内已经构建完成的 `next start`。独立预览容器不挂载宿主源码，使用 `next dev` 不会提供有效热更新，只会在新端口首次访问时按路由重复编译；Figma capture 与浏览器核验直接使用 helper 返回的预编译实例。
