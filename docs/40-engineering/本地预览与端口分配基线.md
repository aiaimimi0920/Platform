# 本地预览与端口分配基线

## 目的

本文档用于承接旧 `legacy source: 本地预览端口规则.md` 中仍然有效的长期开发约束。

---

## 1. 当前正式规则

本地 UI 预览 / 验证默认应：

- 从 `30000` 起使用新的预览端口序列
- 每次新实例按 `+2` 递增

例如：

- `30000`
- `30002`
- `30004`

---

## 2. 当前正式 helper

默认 helper：

- `deploy/start-web-preview.ps1`

若需要重建本地 `docker compose` 的 `web` 服务并拿到新的页面实例：

- `deploy/restart-web-next-port.ps1`

两个 helper 共享同一跨进程端口分配锁。通用预览只有在 Web `/ready` 成功且 `/api/auth/providers` 明确包含 `local-dev` 时才允许返回成功；临时 env 必须在 Docker 创建容器后删除，未就绪实例必须清理。Compose Web 重启必须在健康检查后原子提交 `.runtime/local-web-port.txt`；重启失败时不得覆盖旧 state，也不得遗留未就绪 Web 容器。

---

## 3. 当前正式结论

从现在开始：

- 本地预览与端口分配已有新的 canonical 专题
- 若旧端口规则与本文冲突，以本文与 `AGENTS.md` 为准
