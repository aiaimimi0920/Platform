# 用户级对话日志存档与模型优化数据集基线

## 1. 定位

用户级对话日志存档是 Rust `gateway/` 的正式能力，用于把 authenticated conversation-like 请求在请求期自动归档，供后续质量分析、模型优化、异常排查和人工审核使用。

当前正式策略是：

- 策略名：`ops_forced_full`
- 含义：运维全量强制存档
- 用户侧：无 opt-out
- 请求侧：存档失败不得导致用户请求失败
- 存储侧：元数据入 PostgreSQL，大体量内容入 object storage
- 默认保留期：`180` 天

本基线批准“捕获、查询、导出、清洗抽样、人工审核、发布为平台内数据集资产”六件事；不批准直接启动 fine-tuning、训练、自动标注或任何外部数据共享。

---

## 2. 适用范围

默认归档范围：

- `chat_completions`
- `responses`
- `messages`
- `completions`
- `gemini_generate_content`
- `bedrock_converse`
- `cohere_chat`
- 其他被 `gateway/` 归类为 conversation-like 的 endpoint

默认不归档：

- embeddings
- image / audio / video / music 原始大文件 payload
- health / readiness / metrics
- internal management API

如果非对话能力未来需要归档，必须先补新的数据分类和脱敏规则，不得直接复用对话存档口径。

---

## 3. 数据模型

### 3.1 索引层：`gateway_conversation_archives`

每一条归档记录对应一次 gateway request。

关键字段：

| 字段 | 含义 |
| --- | --- |
| `id` | archive id |
| `request_audit_id` | 对应 `gateway_request_audits.id` |
| `request_id` | gateway runtime request id |
| `project_id` | gateway project |
| `user_id` | 平台用户 id 或 session user id |
| `session_id` | session key / thread key |
| `provider_account_id` | provider account |
| `provider_credential_ref` | 真实凭证引用，禁止存真实 secret |
| `protocol_family` | caller-visible protocol family |
| `protocol_profile` | selected protocol profile |
| `endpoint_kind` | endpoint kind |
| `requested_model` | caller requested model |
| `resolved_model` | route resolved model |
| `status` | `completed / failed / archive_failed / partial` |
| `upstream_status` | upstream HTTP status |
| `failure_class` | provider failure classification |
| `failure_scope` | failure affected scope |
| `request_object_key` | request artifact object key |
| `response_object_key` | response artifact object key |
| `redaction_version` | 脱敏规则版本 |
| `truncated_request` | request artifact 是否被截断 |
| `truncated_response` | response artifact 是否被截断 |
| `archive_error` | 存档失败摘要 |
| `retention_expires_at` | 默认 180 天后过期 |

### 3.2 内容层：object storage artifact

request artifact：

- canonical request
- raw request body（脱敏后）
- metadata
- selected route metadata

response artifact：

- normalized response body 或 raw SSE text（脱敏后）
- usage
- upstream status
- failure summary

所有 object key 必须可由 archive id 推导，便于排查和清理。

## 4. 脱敏规则

必须脱敏的字段名包括但不限于：

- `authorization`
- `cookie`
- `set-cookie`
- `access_token`
- `refresh_token`
- `id_token`
- `session_token`
- `api_key`
- `apikey`
- `apiKey`
- `secret`
- `password`
- `csrf`
- `xsrf`

脱敏原则：

1. 按字段名脱敏优先。
2. 不对普通自然语言内容做激进正则替换，避免破坏训练数据可用性。
3. provider credential payload、browser cookie、OAuth token 不得出现在 archive artifact 中。
4. `provider_credential_ref` 只能存引用、id 或 hash，不得存真实 secret。

当前 redaction version：`v1`.

---

## 5. 请求期行为

请求期归档必须满足：

1. 用户请求主链优先。
2. 归档失败只记录 warning 和 `archive_error`。
3. object storage 写失败时，仍尽量写 DB row，状态为 `archive_failed` 或 `partial`。
4. streaming response 必须在 stream completion callback 中归档。
5. client disconnect 导致 stream 未完整结束时，应记录失败 / partial，而不是误标 completed。

## 6. 内部管理 API

Rust gateway 必须提供内部 management API：

- `GET /v1/internal/gateway/conversation-archives`
- `GET /v1/internal/gateway/conversation-archives/:archiveId`
- `GET /v1/internal/gateway/conversation-archives/:archiveId/artifacts`
- `POST /v1/internal/gateway/conversation-archives/export`
- `GET /v1/internal/gateway/conversation-archives/datasets`
- `POST /v1/internal/gateway/conversation-archives/datasets`
- `POST /v1/internal/gateway/conversation-archives/datasets/:datasetId/review`
- `POST /v1/internal/gateway/conversation-archives/datasets/:datasetId/publish`

默认筛选字段：

- `projectId`
- `userId`
- `providerAccountId`
- `providerCredentialRef`
- `protocolFamily`
- `protocolProfile`
- `endpointKind`
- `requestedModel`
- `resolvedModel`
- `status`
- `failureClass`
- `createdFrom`
- `createdTo`
- `limit`

筛选必须精确匹配；不得使用隐式模糊搜索误导 operator。

## 8. 清洗、抽样、审核与发布

### 8.1 数据集索引层：`gateway_conversation_dataset_exports`

每个数据集导出对应一组 archive 过滤条件与一个清洗后的 NDJSON object。

关键字段：

| 字段 | 含义 |
| --- | --- |
| `id` | dataset export id |
| `status` | `review_pending / approved / rejected / published` |
| `filter` | 生成数据集时使用的 archive 精确过滤条件 |
| `sample_size` | 请求抽样上限 |
| `row_count` | 实际写入 NDJSON 行数 |
| `dataset_object_key` | 清洗后 NDJSON object key |
| `manifest_object_key` | manifest object key |
| `created_by` | 创建者 |
| `reviewer_id` | 审核者 |
| `approval_note` | 通过说明 |
| `rejected_reason` | 拒绝原因 |
| `published_at` | 平台内发布完成时间 |

### 8.2 Object storage layout

数据集 object key 固定为：

- `ai-gateway/conversation-dataset-exports/{datasetId}/dataset.jsonl`
- `ai-gateway/conversation-dataset-exports/{datasetId}/manifest.json`

manifest 必须记录：

- `datasetId`
- `rowCount`
- `sampleSize`
- `filter`
- `status`
- `publishGate`
- `createdAt`

### 8.3 清洗规则

数据集导出会再次执行递归脱敏，至少覆盖：

- `authorization`
- `cookie`
- `set-cookie`
- `apiKey / apikey / api_key`
- `accessToken / access_token`
- `refreshToken / refresh_token`
- `sessionToken / session_token`
- `token`
- `secret`
- `password`

同时会对明显形态的 inline secret 做保守脱敏，例如：

- `Bearer ...`
- `sk-...`
- `sess-...`
- `ya29....`

清洗规则必须保守：普通自然语言 message content 不做激进替换，避免破坏后续质量分析和模型优化数据价值。

### 8.4 抽样规则

v1 抽样为确定性均匀抽样：

- `sampleSize >= total` 时保留全部；
- `sampleSize = 0` 时不写入样本；
- 其他情况在排序后的结果中做稳定均匀取点；
- 同一批过滤条件和相同 archive 顺序下，抽样结果应稳定。

### 8.5 审核与发布闸门

数据集状态机：

```text
review_pending -> approved -> published
review_pending -> rejected
```

正式规则：

1. `POST /datasets` 只创建 `review_pending` 数据集。
2. `review` 只允许 `approve / reject`。
3. `publish` 只允许从 `approved` 进入 `published`。
4. `published` 只表示“平台内可被后续任务引用的数据集资产”。
5. `published` 不等于启动训练、不等于同意外部共享、不等于允许 fine-tuning。
6. 任何训练 / fine-tuning / 外部数据传输都必须另行经过产品与隐私策略审批。

## 9. 与 request audit 的关系

`gateway_request_audits` 继续作为请求观测 / operator 排查索引。

`gateway_conversation_archives` 是更高保真、更重的数据资产索引：

- audit 可没有 artifact；
- archive 必须显式记录 artifact 是否存在、是否截断、是否写入失败；
- archive 通过 `request_audit_id` 与 audit 关联。

---

## 10. 健康状态与 usage 聚合联动

用户级归档与成熟网关硬化同时依赖以下 runtime 状态层：

- `gateway_provider_credential_model_states`
  - 记录 `provider account + provider credential + protocol profile + model` 粒度的健康状态；
  - `credential_invalid / model_unsupported` 进入 `blocked`；
  - `credential_expired / quota_exhausted / rate_limited` 进入 `cooling`；
  - `provider_transient / gateway_protocol_error` 进入 `degraded`；
  - `client_request_invalid / content_rejected` 不惩罚 provider credential；
  - 请求成功会回到 `active`。
- `gateway_usage_aggregates`
  - 从 Redis usage report queue 批量 flush；
  - 聚合维度固定为 `user + provider credential + model`；
  - operator summary 必须显示 queue depth、24h request/failure/token、archive object storage failure 告警。

正式 internal API：

- `GET /v1/internal/gateway/provider-credential-model-states`
- `POST /v1/internal/gateway/usage-aggregates/flush`
- `GET /v1/internal/gateway/usage-aggregates`
- `GET /v1/internal/gateway/usage-aggregates/summary`

---

## 11. 安全边界

- 不允许在 archive 中保存真实 provider secret。
- 不允许在 archive export 中包含 authorization / cookie / token。
- 不允许在 cleaned dataset 中包含 authorization / cookie / token / api key / password。
- 不允许把 archive export 暴露到 public API。
- 不允许把 dataset export 暴露到 public API。
- 不允许用户普通 token 读取其他用户 archive。
- v1 只提供 internal management API，必须受 `GATEWAY_MANAGEMENT_TOKEN` 或等价内部认证保护。
