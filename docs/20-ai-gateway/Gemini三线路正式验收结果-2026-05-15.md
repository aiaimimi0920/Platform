#### 3.1 line2 图片/编辑能力本身已成立

本轮 fresh 登录态下已经 caller-visible 证明：

- `image.url` 可返回可用图片 URL
- `image.b64` 可返回有效 `b64_json`
- `image.edit.single` 可返回编辑后的图片 URL

这意味着 line2 当前不再是“图片能力未实现”。

#### 3.2 line2 长链媒体调用需要更高的 caller timeout 预算

本轮 focused 成功同时确认：

- `image.edit.single`
  - 单次成功 latency 可超过 `400s`
- `music.basic`
  - 单次成功 latency 也可能接近或超过 `300s`

因此如果外部 caller 只给：

- `180s`
- `240s`

之类较短 timeout，容易把最终会成功的请求误判成失败。

#### 3.3 line2 `edit.single` 的 suite 口径已收口到 caller-visible URL 合同

本轮最后一个 false negative 不在 provider 主链，而在 suite 验收口径：

- `edit.single` 已经 `200` 且返回 caller-visible 图片 URL
- 但旧 suite 还会强制做一次二次资产下载
- 该二次下载对 Google-hosted 资源可能仍受 browser session gate 影响，产生 `403`

当前正式口径已改为：

- `line2 image.url`
  - 以 caller-visible 图片 URL 为正式验收边界
- `line2 edit.single`
  - 同样以 caller-visible 编辑结果 URL + 图片 mime type 为正式验收边界
- `line2 image.b64`
  - 继续承担“字节级 materialization”验证职责

这意味着：

- browser-state gated 的二次下载，不再错误地覆盖 caller-visible 成功结果

## 6. 当前最重要的工程说明

本轮真正新增并已验证的 line2 收口点有两个：

1. **fresh session / runtime refresh 是必要条件**
   - 旧 session 漂移后会把 line2 假性打回 signed-out / CookieMismatch / surface 失真
2. **caller timeout 必须覆盖长链媒体 latency**
   - 否则会把最终成功请求误判成超时失败

因此后续若要复现 line2 green 状态，当前默认应同时满足：

- fresh Gemini web session
- refreshed runtime material
- 足够的 caller timeout budget
- line2 图片 / 编辑 URL 型 case 不再强制做 Google-hosted 二次下载验收
