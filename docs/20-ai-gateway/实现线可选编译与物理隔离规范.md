适用范围：

- 当前已重构完成、并且要长期支持“按线停编 / 并行开发 / focused 最小构建”的 AI Gateway 实现线

## 1. 目的

这份规范解决两个不同层次的问题：

1. **按线开关**
   - 某条实现线出问题时，可以直接停掉这一条线的编译
   - focused 开发 / focused live / focused fixture 时，可以只编当前实现线
2. **物理编译隔离**
   - 某条实现线被关闭后，它的真实 owner 模块应尽量不再进入 Rust 编译图
   - 不只是运行时 fail-closed，还要尽量减少“真实实现文件仍被一起编译”的情况

这两层都必须有，不能只做其中一层。

---

## 2. 术语定义

### 2.1 按线开关

指的是：

- 对外提供一条实现线一个 cargo feature
- 默认全开
- 可用 `--no-default-features --features ...` 精确选择构建集合

这层解决的是：

- 是否允许选择性编译
- 是否允许在运行时明确报 `gateway_provider_line_compiled_out`

### 2.2 物理编译隔离

指的是：

- 被关闭的实现线，其真实 owner 模块树尽量不参与编译
- 只允许最外围留下：
  - alias / facade
  - disabled stub
  - compile-time registry 接线

这层解决的是：

- 编译图收缩
- 跨线耦合降低
- 某条线坏掉时，不让它的真实实现继续污染其他 focused 构建

## 3. 当前正式公共行为

### 3.1 默认策略

当前 25 条实现线的 feature 默认必须：

- **全部开启**

也就是：

- 普通 `cargo build / cargo check`
  - 默认仍是完整常用开发态

### 3.2 关闭后的后端行为

当某条实现线被停编时，后端必须：

1. provider account create / update 拦截
2. route preview / access candidate 不再把它当正常候选
3. request execution 直接 fail-closed
4. 返回明确错误：
   - `gateway_provider_line_compiled_out`

禁止行为：

- 静默 fallback 到另一条实现线
- 对 operator 假装“仍然支持”
- 只是 UI 隐藏，但后端仍偷偷尝试执行

### 3.3 前端 / operator 可见性

当前默认允许：

- operator / catalog / inventory 仍保留入口

但后端必须如上明确标记：

- `compiled out`

也就是说：

- **前台可见**
- **后端停编**
- **请求 fail-closed**

## 5. 物理编译隔离的正式要求

### 5.1 真实 owner 模块必须被 gate

实现线的真实 owner 模块树必须优先加到：

- `protocol/<provider>/<line>/...`
- `upstream/<provider>/<line>/...`

关闭时：

- 真实 owner 模块不应继续无条件编译

### 5.2 根级 facade 允许保留，但必须瘦

历史 facade / alias 文件允许保留，例如：

- `protocol/<provider>_web.rs`
- `protocol/<provider>_api.rs`
- `upstream/<provider>_web.rs`

但关闭时它们必须退化成：

- 最薄 disabled stub
- 或最薄 alias

禁止继续在 facade 中塞入真实 owner 逻辑。

### 5.3 共享模块允许存在，但依赖必须显式

某些模块树本身是共享核心，不是单条线独占。

这类情况允许存在，但必须满足：

1. 明确写清楚**哪些实现线依赖它**
2. 只在至少一个依赖线开启时编译
3. 不得因为“历史方便”而长期对所有线无条件编译

## 6. 当前第一批实现线的依赖组规则

### 6.1 AI Studio Web Reverse

owner 模块：

- `protocol/aistudio/web_reverse/**`
- `upstream/aistudio/web_reverse/**`

同时它还 owner：

- `protocol/aistudio/common/**`
- `upstream/aistudio/common/**`

所以当前规则是：

- `line-aistudio-web-reverse` 关闭时，上述两棵 `common`/`web_reverse` 真 owner 树都不应继续参与编译

### 6.2 AI Studio Official / Google Agent Platform Official

这两条线共享一套 Gemini official core。

当前正式 owner 语义是：

- profile 层分成两条：
  - `aistudio_official_api`
  - `google_agent_platform_official_api`
- 但底层官方 send core 允许共享

此外，当前 `aistudio_web_reverse` 的 direct-http send path 也复用了这套官方 core。

因此共享核心的 compile gate 当前应按：

- `line-aistudio-official`
- `line-google-agent-platform-official`
- `line-aistudio-web-reverse`

三者的并集来决定是否编译。

### 6.3 Gemini Web Reverse

owner 模块：

- `protocol/gemini/web_reverse/**`
- `upstream/gemini/web_reverse/**`

但当前 `gemini_canvas_program_web_reverse` 的 bootstrap / invoke helper 仍复用 `protocol/gemini/web_reverse/**` 的一部分协议面。

因此当前协议层 gate 允许按：

- `line-gemini-web-reverse`
- `line-gemini-canvas-program`

### 6.4 ChatGPT Official / Codex OAuth Official

当前 `chatgpt_official_api` 与 `chatgpt_codex_oauth_official_api` 共享一套 ChatGPT official core。

因此共享核心的 compile gate 当前应按：

- `line-chatgpt-official-api`
- `line-chatgpt-codex-oauth-official`

两者的并集来决定是否编译。

### 6.5 ChatGPT Web Reverse

owner 模块：

- `protocol/chatgpt/web_reverse/**`
- `upstream/chatgpt/web_reverse/**`
- `upstream/chatgpt/bootstrap.rs`
- `upstream/chatgpt/execution.rs`

当前规则：

- `line-chatgpt-web-reverse` 关闭时，上述真实 owner 模块树应退化成 disabled stub / 不再参与真实编译

### 6.6 Gemini Canvas Program

owner 模块：

- `protocol/gemini/canvas_program_web_reverse/**`
- `upstream/gemini/canvas_program_web_reverse/**`

当前要求：

- `line-gemini-canvas-program` 关闭时，这两棵真实 owner 树应切成 disabled stub / 不再参与真实编译

### 6.7 Qwen Official

当前 `qwen_dashscope_openai`、`qwen_coding_plan_openai`、`qwen_coding_plan_anthropic` 三个 surface 共享一套 Qwen official core。

当前共享核心 owner：

- `protocol/qwen/official_api.rs`
- `upstream/qwen/official_api.rs`

因此共享核心的 compile gate 当前应按：

- `line-qwen-official-api`

来决定是否编译。

同时：

- `protocol/qwen/mod.rs`
- `upstream/qwen/mod.rs`

必须只在 `line-qwen-official-core` 开启时接入真实 official owner。

### 6.8 Qwen Web Reverse

owner 模块：

- `protocol/qwen/web_reverse.rs`
- `upstream/qwen/web_reverse.rs`

历史 facade：

- `protocol/qwen_web.rs`

当前规则：

- `line-qwen-web-reverse` 关闭时，真实 owner 模块树必须退化成 disabled stub / 不再参与真实编译
- `protocol/qwen_web.rs` 只允许继续保留最薄 legacy facade，不得再回填真实 owner 逻辑

### 6.9 Search Family Official Vendor API

当前 `Perplexity Search / Tavily / Exa / Jina Search / Jina Reader / Linkup / You.com Search / WebSearchAPI Search`
八条线共享同一套 search family common：

- `gateway/src/protocol/search_api.rs`
- `gateway/src/protocol/search_api_disabled.rs`
- `gateway/src/upstream/search_provider_helpers.rs`
- `gateway/src/upstream/search_provider_helpers_disabled.rs`

当前正式规则是：

- 共享 family feature：
  - `family-search-api-compatible-official-api`
- 每家 provider 仍必须继续保留自己的 line feature：
  - `line-perplexity-search-official-vendor-api`
  - `line-tavily-search-official-vendor-api`
  - `line-exa-search-official-vendor-api`
  - `line-jina-search-official-vendor-api`
  - `line-jina-reader-official-vendor-api`
  - `line-linkup-search-official-vendor-api`
  - `line-you-search-official-vendor-api`
  - `line-websearchapi-search-official-vendor-api`

这组 line 的编译归属必须同时满足：

1. family common 只在至少一条 search line 开启时进入编译图
2. `search_api_compatible` / `linkup_compatible` 不能只靠 adapter 名字判 compiled-in
3. 共享 adapter 的真实 line 归因必须继续按：
   - `protocolProfile`
   - 或 `payload.baseUrl`
   判断
4. 当某条 search line 停编时：
   - provider account create/update 必须显式报 `gateway_provider_line_compiled_out`
   - route/access preview 不能静默回退到 generic `search-compatible`
   - 请求执行也不能静默回退到别的 search provider line

## 7. 当前正式编译实现模式

未来新实现线接 compile switch 时，默认必须至少同时落这三层：

### 第 1 层：Cargo feature

- `gateway/Cargo.toml`
- 默认全开
- focused 构建可单线选择

### 第 2 层：运行时 fail-closed

- provider account create/update
- route resolution / preview
- request dispatch

都必须在命中 disabled line 时返回：

- `gateway_provider_line_compiled_out`

### 第 3 层：物理模块树隔离

至少要把这些层真正 gate 起来：

- `protocol/<provider>/<line>/...`
- `upstream/<provider>/<line>/...`
- line 专属 `common/**`（如果它并不是真共享）
- root facade / alias

---

## 8. 当前禁止做法

### 8.1 只做 feature，不做模块树隔离

也就是：

- Cargo.toml 里有 feature
- 但真实 owner 文件仍然全量编译

这不算完成。

### 8.2 只做 UI 隐藏，不做后端 fail-closed

这会让实现线处于半关闭状态，不可接受。

### 8.3 共享模块边界不声明

如果一个模块同时被两条线依赖，必须显式写明：

- 它是共享核心
- 哪几条线依赖它

不能让这种关系只靠聊天记忆存在。

### 8.4 关闭后静默 fallback

关闭某条线后：

- 不得悄悄切到另一条实现线冒充成功

---

## 9. 新实现线接入 checklist

后续任何新的实现线，只要要进入“可选编译”体系，默认 checklist 如下：

1. 定义 canonical 实现线名
2. 定义 public cargo feature 名
3. 明确它的 owner 模块树
4. 明确它依赖哪些共享模块树
5. 为 root facade / alias 增加 disabled stub
6. 为 request dispatch 增加 compiled-out 错误
7. 为 provider account / route preview 增加 compiled-in 检查
8. 增加 focused 单线构建验证
9. 文档同步写入：
   - 本文
   - `AGENTS.md`
   - 相关专题文档

## 10. 当前正式验证要求

至少必须验证：

1. 默认全开：
   - `cargo check`
2. 25 条线分别单线构建：
   - `--no-default-features --features <single-line>`
3. disabled line 命中时：
   - 返回 `gateway_provider_line_compiled_out`

如果还声称“物理编译隔离已推进”，则还应证明：

- 真实 owner 模块已经被 `#[cfg(feature = ...)]` 或 disabled stub 切开
- 不再只是 runtime fail-closed

---

## 11. 当前阶段边界

这份规范当前只要求：

- **已重构完成的实现线**

进入 compile switch + 物理隔离体系。

它当前**不要求**：

- 一次性把整个老 gateway 所有历史 provider / facade / helper 全量 feature 化

所以当前允许存在：

- 历史兼容层
- legacy facade
- 旧 helper

但只要它们与这 25 条线发生边界交互，就必须逐步朝本文要求收口。
