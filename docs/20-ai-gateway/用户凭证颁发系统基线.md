# AI 网关用户凭证颁发系统基线

## 目的

本文档用于承接历史用户凭证颁发系统设计中仍然作为长期规则的结论。

---

## 1. 当前正式定位

用户凭证颁发系统当前负责：

- 当用户购买或获得某种网关访问权益后
- 如何向其颁发平台侧访问凭证

它负责的是：

- 平台访问层凭证

而不是：

- 真实上游 provider secret 发放

---

## 2. 当前正式对象

用户凭证系统当前应至少覆盖：

- 凭证颁发
- 凭证验证
- 凭证撤销
- scope / bundle / project 绑定
- 过期与状态管理

它的输出当前应继续是：

- 平台 `AccessKey` 或等价平台访问凭证

---

## 3. 当前与双层架构的关系

用户凭证颁发系统属于：

- 双层凭证架构中的平台访问层

它不直接负责：

- 真实 provider credential 生命周期
- browser/session runtime
