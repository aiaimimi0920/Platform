# 文档权威与生命周期基线

## 目的

本文档用于固定当前仓库中文档的正式权威顺序与生命周期边界。

后续若再出现：

- 旧文档与新文档互相矛盾
- 进度文档被误当成正式规则
- 分析稿、设计稿、实施总结与正式基线混写

一律以本文为准。

---

## 1. 当前正式权威顺序

当前仓库文档权威顺序固定为：

1. `AGENTS.md`
2. `rules/`
3. `docs/`
4. `docs/50-history/`

解释如下：

- `AGENTS.md`
  - 仓库级自动继承规则
- `rules/`
  - 仓库级守则
  - 负责约束开发行为、测试方式、目录边界、凭证规则、多 AI 规则
- `docs/`
  - 当前正式开发文档树
  - 负责沉淀“当前最终定案”
- `docs/50-history/`
  - 默认视为：
    - 研究材料
    - 阶段计划
    - 施工记录
  - 不自动等价于长期正式规则

---

## 2. 冲突处理规则

### 2.1 规则与文档冲突

若 `rules/` 与 `docs/` 冲突：

- **以 `rules/` 为准**

### 2.2 历史归档与正式文档冲突

若 `docs/50-history/` 与 `docs/` 冲突：

- **以 `docs/` 为准**

---

## 3. 文档生命周期分类

当前所有文档都应明确属于以下某一类。

### 3.1 Canonical

正式长期文档。

位置：

- `docs/`

特点：

- 可直接指导后续开发
- 冲突时优先级最高
- 必须持续维护

### 3.2 Reference

参考文档。

位置：

- 少量独立专题说明

特点：

- 可作为 source material
- 不自动具备当前权威性

### 3.3 Historical

历史施工文档。

位置：

- `docs/50-history/`
- 各类 `实施总结 / 草案 / 风险评估`

特点：

- 保留过程真相
- 不应直接被引用为最终规则

---

## 4. 新文档的默认落点

后续新增文档时，默认遵循：

- 长期规则 -> `rules/`
- 长期正式开发文档 -> `docs/`
- 研究与盘点 -> `docs/50-history/`
- 任务规划 -> `docs/50-history/`
- 施工跟踪 -> `docs/50-history/`

禁止做法：

- 把一次性的实施记录写成新的“总基线”
- 把历史归档文档当作长期 owner 文档

---

## 5. 当前重建原则

当前文档主树已切换完成，后续继续维护时必须遵守：

1. 不机械复制旧文档
2. 先做上位归纳，再做专题下沉
3. 同类主题优先合并成更少的 canonical 文档
4. 历史过程材料统一归档到 `docs/50-history/`
5. 新结论直接进 `docs/`

---

## 6. 当前正式结论

从现在开始，后续开发若遇到文档冲突，应默认：

- 先读 `AGENTS.md`
- 再读 `rules/`
- 再读 `docs/`
- 若问题属于历史过程材料，再读 `docs/50-history/`

这就是当前仓库的正式文档治理口径。
